# End-to-End Performance Test — 2010 Backfill Validation (2026-07-19)

**Scope.** After extending the filing facet store from 2019 back to 2010
(urc_sec_filings: 1.79M → **4,093,579 rows**, every year 2010–2026 populated,
DB 1.67GB/8GB), a ~1,000-point suite was run against **production**
(uniqus-research.vercel.app) with ground truth sampled directly from the
facet store. Harness: `scripts/e2e-perf-test.ts`.

## Test classes

| Class | n | What it proves |
|---|---|---|
| A — filing facet lookups | ~400 | A known filing (stratified across 2010–2026) is findable by form + date + issuer via `/api/es-search` facet path |
| B — auditor facets | 100 | Firm × form × year queries return hits with exact canonical auditor labels |
| C — comment letters | 150 | Thread details return complete conversations; common SEC topics match with excerpts |
| D — EFTS full text | 150 | A known filing is findable by company text through the EFTS path (SEC-rate-limit-respectful) |
| E — issuer enrichment | 100 | `/api/enrich` returns exact tickers/auditors for 1,000 sampled CIKs |

## Results across the three runs

| Run | Condition | Pass | A p50 | A p95 | Wall time |
|---|---|---|---|---|---|
| 1 | right after backfill, original SQL fn | 65.1% | 17,004ms | 17,104ms | 928s |
| 2 | after migration 007 (dynamic plans) | 99.4% | 820ms | 1,931ms | 172s |
| 3 | after migration 008 + route fixes | **97.9%** | **404ms** | **1,355ms** | 175s |

Final per-class: A 97.5% (p50 404ms), B 97.0% (p50 2.4s — year-wide auditor
sweeps), C 100% (p50 176ms), D 96.0% (p50 296ms), E 100% (p50 137–327ms).

## Defects found and fixed (the point of the exercise)

1. **Generic-plan regression (migration 007).** Through PostgREST,
   `urc_search_filings` ran off generic plans — parameter placeholders kept
   the planner from pruning `p_x is null or …` branches. Fine at 1.79M rows;
   at 4.09M it became 17s statement timeouts (100% of run-1 A/B failures were
   HTTP 502). Rewritten as plpgsql dynamic SQL so every call plans with real
   values. REST path: 4.6s → ~0.5s.
2. **View recomputed inside nested loops (migration 008).**
   `urc_current_auditors` was a DISTINCT ON view over 148K Form AP rows;
   nested-loop plans recomputed it per outer row (BlackRock SCHEDULE 13G:
   295 recomputations, 49s). Materialized with a unique index on issuer_cik;
   the weekly auditor load refreshes it via `urc_refresh_current_auditors()`.
3. **Uncapped result counting (migration 008).** `count(*) over ()` scanned
   every match — 20.6s for an unfiltered browse of 4M rows. Totals are now
   capped at 10,000, consistent with EDGAR EFTS itself.
4. **Missing newest-first index (migration 008).** Only composite
   (form, date) indexes existed, so date-ordered browses sorted millions of
   rows. Added `(date_filed desc, accession)`: unfiltered browse 4.7s → 88ms.
5. **Entity-name normalization (es-search route).** Corporate suffixes
   (", Inc.") are made of ultra-common trigrams that blew up the GIN scan
   ("BlackRock, Inc." 36.7s vs "BlackRock" 0.28s), and backslashes in EDGAR
   names ("CORP \DE\") are LIKE escape characters that silently emptied
   results. The route now strips suffixes and escapes LIKE metacharacters.

## Remaining failures (19/905) — artifacts, not product bugs

- **Mega-filer pagination (11).** Vanguard/BlackRock file hundreds of 13Gs on
  a single day; the target accession sits beyond the first 100 rows the
  harness fetches. Pagination through the API retrieves them — correct
  behavior, harness only reads page one.
- **Moss Adams 2026 (3).** Zero current engagements labeled Moss Adams is
  true data — the firm merged into Baker Tilly; latest Form AP rows carry the
  successor firm.
- **Generic text tokens (5).** Harness-chosen words like "ENERGY" /
  "ACQUISITION" match hundreds of same-day filings, pushing the target out of
  the top 50; two zero-hit cases are small filers EFTS doesn't full-text
  index. Product recall via more specific queries is unaffected.

## How to re-run

```sh
set -a && source .env.local && set +a
npx tsx scripts/e2e-perf-test.ts --points 1000 [--base http://localhost:3033]
```

Ground truth resamples on each run (seeded RNG — same sample for a given
build), so the suite stays valid as the corpus grows.
